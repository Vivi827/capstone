# Pally 현 상태 최종 진단

기준일: 2026-09-17  
확인한 저장소: [`puter8/capstone`](https://github.com/puter8/capstone), 커밋 `1d2f93e2ef8fa14df18888792e872df0a378dd3b`  
상태 표기: **확인**은 코드·저장소 문서로 확인한 사실, **판단**은 그 사실에서 도출한 진단, **미검증**은 아직 실험이 필요한 사항이다.

## 결론

**판단:** 지금의 병목은 실제 영어 발화의 절대량보다 Pally가 측정하려는 개념에 맞는 독립 인간 라벨, 적절한 입력 모달리티, 그룹이 분리된 평가 자료의 부족이다. 또 분석기가 계산한 값이 실제 Gemini 응답과 주요 TTS 설정에 전달되지 않아, 모델 정확도를 높여도 사용자가 체감하는 적응으로 곧바로 이어지지 않는다. 따라서 Gemini 파인튜닝이나 새 corpus 대량 수집보다 **측정 정의 → 데이터·split 감사 → 독립 anchor → 적응 정책 연결 → 별도 final 평가**가 우선이다.

## 1. 현재 제품 경로

| 항목 | 확인된 상태 | 실무상 의미 |
|---|---|---|
| STT | Google STT가 음성을 텍스트로 전사하며 자동 구두점은 `false`다. | 물음표·느낌표에만 기대는 질문·에너지 규칙은 서비스 입력과 맞지 않는다. |
| 5축 분석 | `PALLY_AXIS_ANALYZER` 기본값은 `rule`; `ml`과 `hybrid`는 선택 가능하다. 현재 `rule`과 ML 추론은 현재 발화 텍스트 중심이고, `rule`은 전달된 context를 버린다. | 기존 점수는 맥락·원음·사용 이력을 반영한 인간 지각의 검증된 대리값이 아니다. |
| 상태 계산 | 발화 5축에 EMA를 적용해 캐릭터 수치를 만든다. | 수치 계산 자체와 대화 출력 적용은 별개의 단계다. |
| Gemini | 현재 발화, 최근 최대 10개 메시지, 캐릭터 이름, 영어 수준을 사용해 답변을 생성한다. 계산한 축·캐릭터 수치는 `_call_gemini_chat` 인자로 전달하지 않는다. | 적응 정책을 명시해 프롬프트·응답 제어와 연결해야 한다. |
| TTS | 주요 대화 경로는 답변 텍스트를 TTS에 넘기고 기본 속도는 `1.0`이다. | 영어 수준·듣기 선호에 따른 속도 제어와 음성 표현성 적용은 추가 구현이 필요하다. |

근거: [분석기](../work/capstone/ai/analyzers.py), [대화·STT·TTS 경로](../work/capstone/backend/main.py), [축 상태](../work/capstone/ai/matrix_engine.py).

## 2. 데이터와 평가의 현재 위치

| 자료 | 확인된 역할 | 사용 경계 |
|---|---|---|
| 통합 실험 자료 3,137행 | NICT·AMI·Taskmaster 등 실제 발화에 기존 규칙/AI draft 라벨이 섞인 실험 자료 | `human_spoken=true`는 실제 인간이 말한 입력이라는 뜻이지 사람이 5축을 채점했다는 뜻이 아니다. |
| 그룹 제거 후 2,940행 | 기존 dev-200과 겹치는 학습 197행을 제거한 legacy 비교용 자료 | 구 정의의 학습·진단 결과를 새 축의 gold 성능으로 옮길 수 없다. |
| 기존 gold-200 | 이미 여러 진단과 모델 선택에 사용된 인간 평가 자료 | **legacy human dev**. untouched final이 아니다. |
| calibration 후보 90행 | NICT·AMI·Taskmaster 각 30개; 후보의 axes는 비어 있다. | 새 rubric과 입력 조건에 적합한지 확인한 뒤 v2.1 dev anchor 후보로만 사용한다. 독립 채점 완료로 간주하지 않는다. |
| 예약 pool 176행 | legacy 5축 전환용 `final_gate` 106행 + 재현 70행 | 정답·예측을 개발 중 열지 않고, 원본 그룹과 인접 발화까지 보호한다. 새 v2.1 final과 혼합하지 않는다. |

기존 dev-200의 100행이 과거 학습 자료와 같은 canonical 그룹에 있었고 해당 학습 197행을 제거했다. 기록된 성능 영향은 작으므로 누출이 큰 점수 상승을 만들었다고 단정하지 않는다. 예약 pool의 AMI는 1그룹만 참고용이어서 AMI 일반화 결론의 근거가 되지 않는다. 근거: [평가·라벨 계약](../work/capstone/docs/ml-transition-contract.md), [진단 기록](../work/capstone/docs/ml-transition-diagnosis-log.md), [corpus 벤치마크](../work/capstone/docs/real-speech-corpus-benchmark.md).

## 3. 기존 5축의 구조적 불일치

| 기존 축 | 문제 | 새 측정 방향 — 제안 |
|---|---|---|
| Formality | 문어체 격식과 영어 회화의 정중함이 섞일 수 있다. | 발화와 앞선 대화에 나타난 **구어적 공손성**. |
| Energy | 전사 텍스트만으로 실제 억양·강세 변화를 알 수 없다. | 원음을 들을 수 있을 때만 **음성 표현성** 평가; 원음이 없으면 `null`. |
| Intimacy | 문장 속 친근한 단어와 Pally를 오래 사용한 관계 상태는 다르다. | 발화 라벨이 아니라 사용자별 유효 사용 이력·비활성 시간으로 계산한 **관계 친숙도**. |
| Humor | 농담 여부와 밈·유행어의 자발적 사용은 다른 개념이다. | 뜻 질문·인용과 구분한 **밈·유행어 사용**. |
| Curiosity | 일반적인 호기심·지능·학습 의욕으로 오해하기 쉽다. | 사용자가 Pally에게 질문하는 **참여 방식**. 답변 중심은 정상적인 스타일이며 불이익을 주지 않는다. |

이 다섯 항목은 단위가 다르다. 공손성과 음성 표현성은 주로 발화, 관계 친숙도는 사용자·시간, 밈 사용과 질문 참여는 관찰 기간의 사건 집계다. 따라서 한 문장에 언제나 다섯 점수를 강제로 채우면 `0`과 관찰 불가를 혼동한다.

## 4. 현재 결론의 범위

- **확인:** 기존 ML은 규칙·AI draft 라벨을 학습한 실험이 많다. 그 자체로 인간의 스타일 지각을 배웠다고 결론낼 수 없다.
- **확인:** 기존 계약에는 blind CSV, 독립 검수, 부분 라벨, 그룹 분리, 예약 pool 보호 절차가 있다. 다만 새 축 정의에 맞는 완성된 독립 human anchor와 untouched v2.1 final 결과는 확인되지 않았다.
- **미검증:** 새 축의 사람 간 일치도, 음성 입력의 추가 효과, 질문·밈 오탐률, 관계 감쇠 규칙의 사용자 수용성, 실제 Pally 적응의 학습 효과.
- **판단:** 분석기 품질과 적응 정책 품질을 따로 평가해야 한다. 사람과 비슷하게 측정하더라도 Gemini/TTS가 유용하게 변하지 않을 수 있고, 정적 스타일 유사성이 항상 더 좋은 학습 경험을 뜻하지도 않는다.

## 5. 즉시 결정해야 할 사항

1. 새 5항목의 운영 정의·결측 조건·관찰 단위와 사용자에게 보여줄 명칭을 문서 버전으로 고정한다.
2. 기존 train/dev/예약 자료의 원본 대화·화자·학습자·음성·전사 변형 연결을 감사한다.
3. 90개 anchor 후보가 새 정의의 dev 채점에 적합한지 확인하고, 별도 v2.1 final에 쓸 독립 그룹 재고를 계산한다.
4. 정확도 실험 전, 지정된 가상 사용자 상태가 Gemini 답변과 TTS에 실제로 적용되는지를 확인한다.
