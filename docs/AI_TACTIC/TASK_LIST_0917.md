# Pally 실행 작업 목록

기준일: 2026-09-17 · 상태: **제안된 작업**. 체크되지 않은 항목은 완료를 뜻하지 않는다.  
근거: [현 상태 진단](Pally_Current_State_Diagnosis_2026-09-17.md) · [최종 솔루션](Pally_Final_Solution_2026-09-17.md). 작업은 우선순위와 의존성 순서로 배열했다.

## 0단계 — 측정 계약과 자료 보호

- [ ] **T01. 새 5항목의 정의를 v2.1 rubric으로 고정한다.** 공손성, 음성 표현성, 관계 친숙도, 밈·유행어 사용, 질문 참여 방식의 단위·입력·결측·오인 사례를 작성한다. 영어 수준·답변 속도·교정 필요는 성격 축에서 분리한다. **완료 증거:** 예시·경계 사례·`null` 조건이 있는 rubric 버전; 질문이 적은 사용자를 불이익 없이 다루는 정책 검토.
- [ ] **T02. 기존 데이터 역할과 노출 목록을 고정한다.** 실험 3,137행, 그룹 제거 2,940행, legacy dev-200, calibration 후보 90행, 예약 176행의 원본 그룹·해시·접근 범위를 manifest에 기록한다. 예약 pool의 정답과 모델 예측은 열지 않는다. **완료 증거:** train/dev/legacy reserved 노출 manifest와 재현 가능한 생성 로그.
- [ ] **T03. 원본 단위 `split_group_id`를 만든다.** 같은 대화/세션·화자·학습자, 인접 턴, 동일 음성의 재전사·변형을 연결 요소로 묶는다. NICT 등 출처 식별자가 빠진 행은 원본 `source_line`으로 복구하고 실패 행은 격리한다. **완료 증거:** 그룹 연결 감사와 train/dev/예약의 그룹 교집합 보고서.
- [ ] **T04. 새 v2.1 final 적격 그룹 재고를 센다.** 이미 노출된 학습·dev·예약 그룹 및 정확 중복을 제외하고 출처별 독립 그룹 수를 계산한다. **완료 증거:** NICT·AMI·Taskmaster별 남은 그룹·화자·학습자 수와 제외 사유. 이 결과로 final 목표 수량을 확정한다.

**첫 실행 묶음:** T02–T04는 정답 파일을 열지 않고 진행할 수 있다. 새 final을 만들 수 있는지부터 알아야 라벨링 계획이 현실적인지 판단할 수 있다.

## 1단계 — 저장 구조와 사람 기준

- [ ] **T05. 원본·라벨·사용 상태·정책 로그를 분리한 스키마를 만든다.** `samples`, `annotations`, `external_labels`, `observation_windows`, `relationship_state`, `adaptation_log`의 필수 필드와 허용값을 정의한다. legacy loader용 변환 adapter도 설계한다. **완료 증거:** 데이터 사전, JSONL/CSV 예시, `human_spoken`과 `label_origin`의 분리 검증, round-trip 검사.
- [ ] **T06. anchor 후보 90개의 적합성을 감사한다.** NICT·AMI·Taskmaster 각 30개의 발화·직전/다음 턴·출처·짧은 backchannel·noise 여부를 확인한다. 음성 표현성은 원음이 없는 후보에 배점하지 않는다. **완료 증거:** 사용/교체/보류 목록과 이유; 새 rubric의 dev 용도로만 승인.
- [ ] **T07. blind 독립 채점을 진행한다.** 최소 20% 이상 2인 중복, 작은 anchor에서는 가능한 한 전체 중복 채점한다. 평가자별 별도 파일과 서로 다른 무작위 순서, 출처·AI 점수 숨김, 점수 근거와 수정 로그를 적용한다. **완료 증거:** 평가자별 원점수·근거·시드·버전·독립성 기록. 비정상적 exact agreement가 있으면 확인 전 보류하며 부정행위를 단정하지 않는다.
- [ ] **T08. 원점수로 축별 일치도를 계산하고 rubric을 수정한다.** ICC, Spearman, MAE, 정확 일치율, 결측률과 불일치 사례를 조정 전 원점수로 보고한다. 조정 후 점수는 별도 버전으로 보존한다. **완료 증거:** 축별 지표·표본 수·대표 불일치·rubric 변경 로그; dev 입력 조건(text+context/audio)을 명시.

## 2단계 — 새 final 선정과 제품 적응 경로

- [ ] **T09. v2.1 final을 독립 그룹에서 선정·봉인한다.** 목표안은 자연 표본 120개(출처별 40)와 challenge 30개(각 10)다. T04에서 충분한 그룹이 확인되지 않으면 수량·범위를 조정하고 같은 그룹에서 발화를 추가해 채우지 않는다. 음성 final은 원음 확보 후 별도로 설계한다. **완료 증거:** 그룹 교집합 0, seed·원본 hash·선정/제외 사유가 있는 비공개 manifest, 자연/challenge 분리.
- [ ] **T10. 적응 정책을 측정기와 분리해 구현한다.** 우선순위는 사용자 명시 요청 > 영어 수준·학습 지원 > 현재 상황 > 장기 성향 > 기본값. 숫자를 Gemini용 실행 지침으로 바꾸고, TTS 속도는 영어 수준·듣기 선호로 정한다. **완료 증거:** 정책 버전·프롬프트 버전·TTS 제어값·실제 응답을 잇는 `adaptation_log`.
- [ ] **T11. 가상 사용자 상태로 출력 변화부터 검증한다.** 분석기를 연결하기 전 지정한 정중/캐주얼, 차분/활기 상태를 주입해 답변 텍스트와 음성이 기대한 방향으로 달라지는지 검토한다. **완료 증거:** 고정 입력 비교 사례, 실패 유형, 사용자 요청과 학습 지원의 우선순위 테스트.

## 3단계 — 축별 측정기

- [ ] **T12. 구어적 공손성과 질문 사건을 측정한다.** 현 `rule`을 baseline으로 두고 사람 dev와 비교한다. 질문은 STT 물음표만 사용하지 않고 정보 질문·듣기 지원·역할극 지시를 구분한 뒤 충분한 자유 대화 구간에서 집계한다. **완료 증거:** 축별 MAE/상관 또는 분류 오탐·누락, 기회 부족 시 `null` 처리.
- [ ] **T13. 관계 친숙도 계산기를 만든다.** 유효 사용 이벤트, 반복 사용, 마지막 활동 이후 경과시간을 버전 있는 계산식으로 구현한다. 한 단어·한 발화로 상태를 바꾸지 않는다. **완료 증거:** 같은 이벤트 재처리의 동일 결과, 중복·시각 경계·시간 감쇠 테스트, 사용자 반응 검토.
- [ ] **T14. 밈·유행어 사건을 판별한다.** 검수된 소규모 표현 목록에서 시작하고 Gemini의 문맥 판단으로 자발적 사용, 뜻 질문, 인용, 따라 읽기, Pally 유도 사용을 구분한다. 새 표현의 최신성은 날짜·출처가 있는 근거로 확인한다. **완료 증거:** 버전 있는 목록, 어려운 사례의 오탐·누락 보고. Reddit API 연결은 시작 조건이 아니다.
- [ ] **T15. 원음 연결 후 음성 표현성을 검증한다.** 사용자 발화의 실제 음성 구간을 `audio_ref`에 연결한다. 인간 청취 점수와 음성 모델/간단한 음향 특징을 비교한다. 텍스트 전용 사례는 `null`을 유지한다. **완료 증거:** 음성 품질·구간 정합성 감사, audio human dev, 텍스트 대조군 대비 효과.

## 4단계 — 고정 평가와 출고 판단

- [ ] **T16. final 열람 전에 실험 계약을 동결한다.** rubric, train 파일 hash, 그룹 manifest, 측정기·Gemini·적응 정책 버전, 비교 baseline, 축별 지표, 출처별 결과, 그룹 단위 불확실성 계산법을 고정한다. **완료 증거:** 날짜·해시·승인자가 있는 평가 계획; 예약 legacy pool과 새 v2.1 final의 목적 분리.
- [ ] **T17. untouched final을 한 번 평가한다.** 자연 표본을 주요 결과, challenge를 보조 진단으로 보고한다. 독립 대화·화자·학습자 수와 corpus 구성, 결측률을 함께 발표한다. 결과를 보고 수정하면 그 자료는 이후 dev로 재분류한다. **완료 증거:** 재현 가능한 결과와 오차·한계 보고.
- [ ] **T18. 실제 적응 효과를 별도로 검증한다.** 고정 Pally와 점진 반영 Pally를 비교하되 응답 선호·편안함·영어 학습 지원을 각각 측정한다. 사람과 유사한 점수 예측만으로 더 좋은 학습 효과를 주장하지 않는다. **완료 증거:** 사용자 평가 설계와 결과; 지표별 채택·보류 결정.
