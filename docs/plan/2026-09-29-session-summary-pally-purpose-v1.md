# Pally 대화 목적 실험 (purpose-v1) — 세션 진행 요약

이 문서는 `feat/pally-purpose-aware-experiment-v1` 브랜치에서 진행한 작업 전체를 정리한 것입니다. 실험의 최종 판정에 영향을 줄 수 있는 세부 사항(블라인드 평가의 X/Y↔조건 매핑, 목적 라벨 동률 항목의 구체적 타이브레이크 절차)은 이 문서에 적지 않았습니다 — 해당 부분은 "워크북 결과와 PM의 선택을 바탕으로 생성"했다는 사실만 기록합니다.

## 1. 배경

PM 최종 실험설계서(`Pally_Communicative_Purpose_Aware_Experiment_Design_2026-09-22.md`, PR#87)를 기준으로, 조건 A(Direct)와 조건 B(Purpose-aware)를 비교하는 실험을 실행 가능한 상태까지 만드는 것이 이번 세션의 목표였습니다. 핵심 연구 질문은:

> 동일한 사용자 발화와 동일한 3축(Formality/Humor/Curiosity) 예측을 쓰는 조건에서, 예측된 대화 목적을 응답 생성기에 명시적으로 추가하면 중의적·비격식 표현의 의미와 화자 태도를 보존하면서 자연스럽게 이어지는 응답이 더 많이 나오는가?

설계서 §1은 "목적 분류기 자체의 분류 성능을 주된 contribution으로 주장하지 않는다"고 명시하고 있어, 분류기 정확도는 진단용 보조 지표이고 실제 결론은 Phase 3 블라인드 평가에서 나옵니다.

## 2. 데이터셋 (100개) 품질 감사 및 수정

세션 시작 시점에는 100개 항목(clear 30 / ambiguous-informal 40 / surface-shortcut 30, 학습 80 / 최종실험 20)이 이미 조립되어 있었으나, 사용자가 엑셀 워크북에서 `context_before`(이전 문맥) 필드가 "Um.", "Yeah." 같은 의미 없는 필러로 채워진 것을 발견하면서 전면 재검토가 시작됐습니다.

### 2.1 전수 감사

100개 전체를 설계서 §4.1/§7/§8/§9/§10과 항목별로 대조하는 감사를 실행해 다음을 확인:
- `context_before` 필러(의미 없는 backchannel) 49개, `null` 1개
- 문맥이 아예 없거나(대화 첫 턴) 실제 원문 대조 결과 의도한 중의성이 성립하지 않는 항목 2개
- 대화행위(dialogue act) 분절로 문장이 중간에 끊긴 항목 1개, 반어법 핵심 문장이 빠진 항목 1개
- 전사 과정에서 남은 자잘한 깨짐(스트레이 숫자·중복 단어·플레이스홀더) 7건
- surface-shortcut 5개 항목의 `literal_or_nonliteral`이 관용적 의미인데도 "literal"로 잘못 표기
- 학습/최종실험에 동일 n-gram("no way")이 걸쳐 있어 발생할 수 있는 특징 레벨 누출 위험
- 부적절한 성적 내용이 섞인 문맥 1건

### 2.2 수정

- 필러 문맥 49개 중 38개는 같은 대화 내에서 실제 의미 판단에 쓸 수 있는 더 앞 턴으로 교체, 11개는 설계서 규정대로 `null` 처리
- 문맥 복구가 불가능하거나 중의성이 성립하지 않는 항목은 같은 유형의 다른 실제 발화로 교체
- 문장이 끊긴 항목은 원문 전체로 복원
- 전사 깨짐 정리, `literal_or_nonliteral` 오표기 정정
- 부적절한 문맥은 대상 발화 자체가 문맥 없이도 의미가 통해 `null` 처리
- 학습/최종실험 간 n-gram 누출은 항목 1개씩 맞교환으로 해소
- PM 피드백으로 추가 지적된 약한 항목 4개(자체적으로 "약한 중의성"이라 표시된 관용구, 범용 관용구라 함정으로 약한 슬랭 트랩)를 더 명확한 예시로 교체

재검증 결과: 스키마 100/100 완비, lexical family 상한(2개) 초과 0건, family의 학습/최종실험 분할 위반 0건, 슬라이스별 정확히 24/6·32/8·24/6, 중복 target_turn 0건, 민감 키워드 재스캔 0건 — 전부 통과.

## 4. Phase 1 — 목적 분류기 + 3축 회귀기

### 4.1 인간 라벨 수집·집계

4인(윤서/minju/eunheay/chanhee)이 엑셀 워크북으로 100개 전체에 대해 `purpose_primary`+3축을 독립적으로 채점 완료(각자 96~100개 완전 응답). 최종실험 20개의 응답 채점 기준(`required_response_properties`/`forbidden_errors`/`continuation_anchors`/`continuation_probe`)은 워크북 결과와 PM의 선택(4인 짝수라 결과가 갈렸을 시 pm의 선택을 기준)을 바탕으로 20개 전부 확보.

`scripts/aggregate_pally_purpose_v1_labels.py`를 새로 작성해 4인 라벨을 합의 라벨로 집계:
- 축 점수: 4인 중앙값, 5점 단위 반올림
- 목적: 3인 이상 다수결. 다수결이 안 나온 23개는 워크북 결과와 PM의 선택을 바탕으로 합의 라벨 생성

### 4.2 라벨 신뢰도

- 목적: Fleiss' kappa 0.311(원래 fair 수준), 평균 쌍별 일치율 62.5%, 4인 다수결 성공 77/100
- 3축: Formality ICC(1,k) 0.474, Humor 0.686, Curiosity 0.835 (Formality가 가장 편차 큼)

### 4.3 모델 학습 및 정확도 문제 발견·진단

TF-IDF(word 1-2gram + char 3-5gram) + LogisticRegression(class_weight=balanced)으로 학습 후, 최종실험 20개에 대해 held-out 정확도를 측정한 결과 **45%(다수 클래스 기준선 55%보다 낮음)**로 확인. confusion matrix상 다수 클래스(acknowledge_empathize) 외 5개 목적을 전혀 못 맞힘.

원인 진단:
- `acknowledge_empathize`가 전체 100개 중 69개로 극단적으로 쏠려 있었음(다른 목적은 3~13개)
- 정보 전달성 발화(회의록 통계 문장 등)가 습관적으로 "acknowledge_empathize"로 채점된 패턴 발견 → 설계서 §6 범주 경계 규칙에 따라 19개를 재검토해 명확히 안 맞는 것은 다른 목적으로 재분류(69→50개로 완화)
- 재분류 후에도 held-out 정확도는 오히려 45%→더 낮아짐(더 정직한 숫자로 확인) — Leave-One-Out 교차검증으로 LogisticRegression/MultinomialNB/kNN(k=1,3) 4개 모델을 비교했지만 전부 다수결 기준선 근처이거나 이하 → **모델·라벨 문제가 아니라 클래스당 학습 샘플 수(일부 목적은 1~9개) 자체의 근본적 한계**로 결론
 - 즉 "전체 100개가 적다"기보다 **"6종 목적으로 나누다 보니 일부 목적은 학습 샘플이 1~9개밖에 안 남는다

### 4.4 Codex 자문

`/codex consult`로 독립적 2차 의견을 구함. 요지:
- 정확도(45%)가 다수결 기준선(55%)보다 낮다는 건 6종 목적 구분이 유효하다는 주장을 뒷받침 못 하는 게 맞음
- 다만 라벨 신뢰도(Fleiss' kappa 0.311)가 이미 분류기 정확도의 상한을 낮춰놓은 것으로, 표본 부족만의 문제가 아님
- 학습 스크립트가 `target_turn`만 쓰는데 인간 라벨러는 `context_before`도 봤다는 정보 비대칭 지적
- 권고: 6종 범주 통합(사후 조정처럼 보일 위험) 대신, 현재 분할·모델·6종 체계를 고정하고 분류 실패를 정식 결과로 투명하게 보고 → 예정된 블라인드 A/B 평가를 그대로 진행 → 논문 결론은 "6종 목적 분류가 유효하다"가 아니라 "현재 구현된 목적 예측 파이프라인이 응답 품질에 어떤 영향을 주는가"로 범위를 좁혀 서술

이 권고를 그대로 채택.

## 5. Phase 2 — A/B 응답 생성

`scripts/run_purpose_aware_generation.py`로 최종실험 20개에 대해 Gemini 2.5 Flash Lite로 조건 A/B 응답을 실제 생성(총 40개). 첫 실제 호출을 수동으로 검증("Paul saved my ass"를 관용구로 올바르게 해석함을 확인) 후 나머지 19개 배치 실행.

- 조작 점검(A/B가 동일한 3축 예측값 공유, B만 목적 노출)을 코드 assertion으로 자동 검증 — 전부 통과
- 품질 스캔: 빈 응답·과도하게 긴 응답·에러 없음. 다만 3개 항목(090, 093, 098)은 목적 정보를 넣어도 A/B 응답이 완전히 동일하게 생성됨(temperature=0이라 발생 가능한 정상적 현상, 블라인드 평가에서는 자동으로 "동률" 처리될 것으로 예상)

## 6. Phase 3 — 블라인드 평가 준비

### 6.1 엑셀 워크북 (1차 시도)

설계서 §12(블라인드 절차)·§13(rubric) 기준으로 4개 워크북 생성 스크립트(`scripts/export_pally_purpose_v1_blind_eval_workbook.py`) 작성 — X/Y 익명화, 평가자·항목별 순서 무작위화, `좋은 응답`/`승자` 자동 계산 수식 포함.

**버그 발견 및 수정**: openpyxl에서 빈 행(`ws.append([])`)을 쓰면 `max_row`가 그 행을 안 세는데 내부 append 커서는 카운트하는 차이 때문에, 헤더 행 번호 계산이 1행 밀리는 버그를 발견 — 헤더 3개 칸("좋은응답(자동)" 등)에 제목 대신 수식 텍스트가 잘못 들어감(실제 데이터 행 수식 자체는 정상이라 채점 기능엔 지장 없었음). 행 번호를 하드코딩하는 방식으로 수정.

### 6.2 웹앱(Artifact)으로 전환

엑셀 가독성 문제로 사용자 요청에 따라 Google Forms 대안을 검토했으나(OAuth 설정 부담이 커서 보류) 최종적으로 **Claude Artifact(웹페이지+공유 DB)** 로 블라인드 채점 도구를 신규 제작:

- 이름 선택(윤서/minju/eunheay/chanhee) → 그 사람 순서로 섞인 20개 항목을 한 번에 하나씩 보여주는 단일 페이지 앱
- 항목마다 문맥/발화, 참고 정보(접이식), X/Y 응답 카드, 중대오류 Y/N, 5개 항목 1-5점 클릭형 버튼, "좋은 응답 통과"·"승자" 실시간 자동 계산
- `db` capability로 자동 저장 — 중간에 껐다 켜도 이어서 가능
- 발행 후 `ArtifactData`로 실제 쓰기/읽기 테스트를 거쳐 동작 확인
- 결과는 Claude가 직접 DB에서 읽어서 집계 가능(사용자가 파일을 별도로 내보낼 필요 없음)
- 페이지는 기본적으로 비공개이며, 사용자가 직접 공유 메뉴에서 팀원에게 권한을 부여해야 접근 가능함을 안내함

### 6.3 진행 현황

- eunheay(C) 슬롯: 20/20 완료
- 윤서·minju·chanhee: 진행 중

집계 방식(§13.5): 항목별로 4인 중 3명 이상이 같은 판정(X승/Y승/동률/둘다부적합)을 내려야 확정. 1인 결과만으로는 최종 결론을 내리지 않음.
